# 一、模块三：AI引擎与多模态解析服务

## 1.1 开发模式选择

### 1.1.1 后端架构模式

| 模式 | 选择 | 应用场景 |
|------|------|---------|
| API 架构 | **Next.js Route Handlers** (App Router) | 所有 API 均使用 `export async function POST(req: Request)` |
| AI SDK | **双轨制**：`ai` SDK (Vercel) + 自研 `OpenAICompatibleClient` | chat/advice-stream 使用 `streamText` 从 `ai` 包；parse/image/tef/suggestions 使用自研客户端 |
| 流式传输 | **SSE (Server-Sent Events)** | chat + advice-stream 使用 SSE 流式输出，前端逐字渲染 |
| 多模态输入 | **FormData + Base64** | 图片上传经 Canvas 压缩后转 Base64 DataURI |
| AI 配置传递 | **HTTP Header** (`x-ai-config`) | 客户端 AI 配置通过请求头传递，避免持久化 API Key 到服务端 |
| 响应格式约束 | **JSON Schema** (`response_format: json_object`) | 解析类 API 强制 AI 返回 JSON，避免解析歧义 |
| 并发策略 | **Promise.all** 并发调用 | smart-suggestions 6 个维度的建议并发生成 |
| 错误处理 | **降级兜底** | API 失败返回默认值（如 TEF 乘数=1.0），不阻塞前端 |

### 1.1.2 双轨 AI 客户端策略

```

│                   Snapit-AI AI 调用架构                        │
├──────────────────────────────────────────────────────────────┤

### 1.1.3 数据流设计

```
前端 Client Component
    │
    ├── 文本解析请求
    │     fetch("/api/openai/parse", {text, type, userWeight})
    │     header: x-ai-config = JSON.stringify(aiConfig)
    │       │
    │       ▼
    │     parse/route.ts
    │       ├── 获取 aiConfig.agentModel
    │       ├── new OpenAICompatibleClient(baseUrl, apiKey)
    │       ├── 组装 Prompt（结构化 JSON 输出约束）
    │       ├── client.generateText({model, prompt, response_format: "json_object"})
    │       └── 解析 result → uuidv4() 分配 log_id → JSON Response
    │
    ├── 图片解析请求
    │     fetch("/api/openai/parse-with-images", FormData)
    │       │
    │       ▼
    │     parse-with-images/route.ts
    │       ├── formData.get("image0"..."image4") — 最多5张
    │       ├── imageBuffer → Buffer.from → base64 → `data:${mime};base64,...`
    │       ├── 获取 aiConfig.visionModel
    │       ├── client.generateText({model, prompt, images: [dataURIs], response_format})
    │       └── JSON.parse → uuidv4() → Response
    │
    ├── AI 聊天请求
    │     useChat({api: "/api/openai/chat", headers, body})
    │       │
    │       ▼
    │     chat/route.ts
    │       ├── 解析 body: {messages, userProfile, healthData, recentHealthData, expertRole, aiMemory}
    │       ├── 解析 header: x-ai-config → aiConfig.chatModel
    │       ├── 动态组装 systemPrompt（用户资料+健康数据+历史趋势+AI记忆）
    │       ├── createOpenAI({baseURL, apiKey}) + streamText({model, system, messages})
    │       └── result.toDataStreamResponse() → SSE 流式输出
    │
    └── 智能建议请求
          fetch("/api/openai/smart-suggestions", {dailyLog, userProfile, recentLogs})
            │
            ▼
          smart-suggestions/route.ts
            ├── 准备 dataSummary（today + profile + recent 7天）
            ├── 6 组专业 Prompt 定义（nutrition/exercise/metabolism/behavior/timing/wellness）
            ├── Promise.all(6 × client.generateText({response_format: "json_object"}))
            └── 按 priority 排序 → JSON Response
```

## 1.3 OpenAICompatibleClient 设计

### 1.3.1 类架构

```
┌──────────────────────────────────────────────────────────────┐
│              OpenAICompatibleClient                           │
├──────────────────────────────────────────────────────────────┤
│ 构造函数                                                     │
│   constructor(baseUrl: string, apiKey: string)                │
│     自动处理 baseUrl 结尾斜杠和 /v1 后缀去重                  │
│     记录初始化日志（baseUrl, hasApiKey）                      │
├──────────────────────────────────────────────────────────────┤
│ 核心方法                                                     │
│   createChatCompletion({model, messages, response_format?, stream?})
│     → fetch POST `${baseUrl}/v1/chat/completions`            │
│     → 构建标准 OpenAI request body                            │
│     → 非 OK 抛异常（含 errorText）                           │
│     → 返回原始 Response（流/非流）                            │
│                                                              │
│   generateText({model, prompt, images?, response_format?})     │
│     → 有 images: messages[0].content = [{text}, ...image_url] │
│     → 无 images: messages[0].content = prompt                │
│     → createChatCompletion() → response.json()               │
│     → 返回 {text: response.choices[0].message.content}       │
│                                                              │
│   streamText({model, messages, system?})                      │
│     → system 存在时 messages 头部插入 system 消息             │
│     → createChatCompletion({stream: true})                   │
│     → 返回 Response（流式 body）                              │
│                                                              │
│   listModels()                                                │
│     → fetch GET `${baseUrl}/v1/models`                       │
│     → 返回 OpenAI ModelList JSON                             │
└──────────────────────────────────────────────────────────────┘
```

### 1.3.2 关键设计决策

- **baseUrl 智能规范化**：自动处理 3 种常见输入（`https://api.openai.com`、`https://api.openai.com/`、`https://api.openai.com/v1`），确保最终请求 URL 正确拼接
- **视觉输入**：`generateText` 的 `images` 参数接收 `data:image/...;base64,...` 数组，构建 OpenAI Vision API 兼容的消息数组
- **错误透传**：非 OK 响应读取 `errorText` 并附在异常消息中，方便调试
- **集中日志**：所有关键节点（初始化、请求参数、响应状态）均有 console.log 记录

### 1.4.2 食物解析 Prompt 设计

```
核心约束:
  - 请直接输出 JSON，不要有额外文本
  - 如果无法确定数值，请给出合理估算，标记 is_estimated: true
  - response_format: { type: "json_object" } 强制 JSON 输出

解析字段（per food item）:
  log_id             ← 服务端填充 uuidv4()，不依赖 AI 生成
  food_name          ← AI 识别/推理
  consumed_grams     ← AI 根据描述或图片估算
  meal_type          ← breakfast/lunch/dinner/snack
  time_period        ← morning/noon/afternoon/evening（根据文本/图片推断）
  nutritional_info_per_100g:
    calories, carbohydrates, protein, fat, fiber?, sugar?, sodium?
  total_nutritional_info_consumed ← AI 基于 consumed_grams 按比例计算
  is_estimated       ← 标识是否 AI 估算
```

### 1.4.3 运动解析 Prompt 设计

```
额外参数: 用户体重 (用于卡路里估算公式: METs × 体重 × 小时)

解析字段（per exercise item）:
  log_id                     ← 服务端 uuidv4()
  exercise_name              ← 运动名称
  exercise_type              ← cardio | strength | flexibility | other
  duration_minutes           ← 持续时长
  distance_km?               ← cardio 特有
  sets?, reps?, weight_kg?   ← strength 特有
  estimated_mets             ← 代谢当量
  user_weight                ← 用户体重
  calories_burned_estimated  ← METs × 体重 × (duration_minutes/60)
  muscle_groups              ← 如 ["腿部", "核心"]
  is_estimated               ← 标识
```

### 1.4.4 图片传输流程

```
前端 Canvas 压缩 (lib/image-utils.ts)
    │
    ├── compressImage(file, maxSizeBytes)
    │     │
    │     ├── file.size ≤ maxSizeBytes → 直接返回
    │     │
    │     ├── 创建 img 元素加载
    │     ├── Canvas 等比例缩放到 MAX_WIDTH×MAX_HEIGHT (1920×1080)
    │     ├── quality 从 0.9 递减到 0.1，逐档尝试
    │     │     canvas.toBlob(mimeType, quality) → 直到 size ≤ maxSizeBytes
    │     └── 最低质量仍超标 → 使用 quality=0.1 强制输出
    │
    ▼
FormData 提交
    │
    ├── formData.append("text", text)
    ├── formData.append("type", "food"|"exercise")
    ├── formData.append("userWeight", weight)
    ├── formData.append("aiConfig", JSON.stringify(aiConfig))
    └── formData.append("image0", file0) ... formData.append("image4", file4)
    │
    ▼
服务端 Base64 转换
    │
    ├── image.arrayBuffer() → Buffer.from(buffer).toString("base64")
    └── `data:${image.type};base64,${imageBase64}`
```

## 1.5 AI 聊天 API 设计（核心）

### 1.5.1 系统提示词动态组装算法

```
chat/route.ts: POST handler
  │
  ├── 1. 解析请求
  │     body: {messages, userProfile, healthData, recentHealthData, systemPrompt, expertRole, aiMemory}
  │     header: x-ai-config → aiConfig.chatModel
  │
  ├── 2. 验证配置
  │     chatModel.name + baseUrl + apiKey 三者缺一不可
  │
  ├── 3. 构建 systemPrompt（逐步追加）:
  │     │
  │     ├── 基础层: customSystemPrompt || "你是 SnapFit AI 健康助手..."
  │     │
  │     ├── 用户资料层 (有 userProfile 时):
  │     │     体重/身高/年龄/性别 → 中文映射（male→男，female→女）
  │     │     活动水平 → 中文映射（sedentary→久坐不动...）
  │     │     健康目标 → 中文映射（lose_weight→减重...）
  │     │     专业模式字段: medicalHistory/lifestyle/healthAwareness
  │     │
  │     ├── 今日健康数据层 (有 healthData 时):
  │     │     weight/BMR/TDEE/摄入/消耗/净卡路里/热量缺口
  │     │     宏量营养素占比（g + 卡路里百分比）
  │     │     dailyStatus → formatDailyStatusForAI()
  │     │     tefAnalysis → 基础TEF/增强乘数/增强因素
  │     │
  │     ├── 今日食物明细 (foodEntries.length > 0):
  │     │     per entry: name(g): kcal, 蛋白Xg, 碳水Xg, 脂肪Xg, 餐次, 时间
  │     │
  │     ├── 今日运动明细 (exerciseEntries.length > 0):

### 2.3.2 核心交互流程

**流程 1：切换专家**

```
用户点击专家按钮
  → handleExpertSelect(expertId)
  → setSelectedExpert(expertId)
  → useEffect 触发（依赖 selectedExpert）
    → isLoadingMessagesRef.current = true
    → 从 allExpertMessages[expertId] 加载消息
    → setMessages(expertMessages || [])
    → setTimeout(() => isLoadingMessagesRef.current = false, 0)
    → 移动端: setShowExpertPanel(false)
```

**流程 2：发送消息**

```
用户输入文本 + 回车/点击发送
  → onSubmit(e)
  → 检查 isClient && checkAIConfig()
    ├── AI 未配置 → toast 提示 → return
    └── 配置就绪 → handleSubmit(e)
        ↓
      useChat 自动发起 POST /api/openai/chat
        header: x-ai-config, x-expert-role
        body: {userProfile, healthData, recentHealthData, systemPrompt, expertRole, aiMemory}
        ↓
      后端 chat/route.ts 处理 → SSE 流式响应
        ↓
      useChat 接收 chunk 流 → messages 实时更新 → 触发重渲染
        ↓
      onFinish → 消息保存到 allExpertMessages[selectedExpert]
```

**流程 3：消息自动持久化**

```
useEffect 监听 [messages, selectedExpert]:
  if (messages.length > 0 && !isLoadingMessagesRef.current) {
    const newMessages = {...allExpertMessages}
    newMessages[selectedExpert] = messages
    setAllExpertMessages(newMessages)  // → localStorage 同步
  }
```

**流程 4：AI 记忆更新联动**

```
AI 回复完成 → EnhancedMessageRenderer 解析 [MEMORY_UPDATE_REQUEST]
  → 提取 newContent + reason
  → 渲染可编辑确认卡片
  → 用户点击"确认"
    → handleMemoryUpdateRequest(newContent, reason)
      → useAIMemory().updateMemory({expertId: selectedExpert, newContent, reason})
        → IndexedDB.saveData(expertId, newMemory)
        → setMemories(prev => ({...prev, [expertId]: newMemory}))
        → toast("记忆已更新")
```

## 2.5 EnhancedMessageRenderer 设计

### 2.5.1 流式内容解析状态机

```
parseStreamingContent (useMemo, 依赖 content):

输入: raw content string（可能不完整，接收自 SSE 流）

解析目标:
  ┌─────────────────────────────────────────────┐
  │ 检查顺序:                                    │
  │  1. [MEMORY_UPDATE_REQUEST] 记忆更新请求     │
  │  2. <think> 思考过程标签 (DeepSeek 等模型)    │
  │  3. [思考过程]/[回答] 中文标记               │
  │  4. JSON {reasoning_content, content} 格式   │
  │  5. 普通 markdown 文本                       │
  └─────────────────────────────────────────────┘

对记忆更新请求:
  regex: /\[MEMORY_UPDATE_REQUEST\][\s\S]*?新记忆内容[：:]\s*([\s\S]*?)\s*更新原因[：:]\s*([\s\S]*?)\s*\[\/MEMORY_UPDATE_REQUEST\]/i
  
  分段:
    contentBeforeMemory ← 记忆标记之前的内容
    memoryRequest       ← {newContent, reason}
    contentAfterMemory  ← [/MEMORY_UPDATE_REQUEST] 之后的内容

对思考过程:
  regex: /<think>([\s\S]*?)(<\/think>|$)/i
  
  提取:
    reasoning          ← <think> 标签内内容
    hasCompleteReasoning ← 是否有 </think> 闭合标签
    mainContent        ← 去除 <think>...</think> 后的内容

返回值:
  {
    reasoning, mainContent, hasCompleteReasoning, hasReasoning,
    memoryRequest, hasMemoryRequest, hasCompleteMemoryRequest,
    contentBeforeMemory, contentAfterMemory
  }
```

```

### 3.2.3 导出/导入数据流

```
导出 (handleExportData):
  ├── 1. indexedDB.open("healthApp", 2)
  │      healthLogs store → openCursor → 遍历所有 → allData
  │      aiMemories store → openCursor → 遍历所有 → allMemories
  ├── 2. 构建 exportData = {userProfile, aiConfig, healthLogs, aiMemories}
  ├── 3. JSON.stringify + data URI + <a> download
  └── 4. localStorage.setItem('lastExportTime', new Date().toISOString())

导入 (handleImportData):
  ├── 1. FileReader.readAsText(file) → JSON.parse
  ├── 2. 验证: userProfile + healthLogs 必须存在
  ├── 3. setUserProfile(importedData.userProfile)
  ├── 4. setAIConfig(importedData.aiConfig)
  ├── 5. IndexedDB healthLogs:
  │      openCursor → objectStore.clear() → objectStore.add(data, key) 逐条写入

## 3.3 国际化架构设计

### 3.3.1 全链路国际化方案

```
┌──────────────────────────────────────────────────────────────┐
│              Snapifit-AI 国际化 (next-intl)                    │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  1. 路由层 (middleware.ts)                                   │
│     createMiddleware({locales: ['zh','en','ja','ko','de'],   │
│       defaultLocale: 'zh', localePrefix: 'always',           │
│       localeDetection: true})                                │
│     matcher: 匹配所有非 api/_next/静态资源的路径              │
│     效果: /chat → /zh/chat (always prefix)                   │
│                                                              │
│  2. 布局层 (layout.tsx)                                      │
│     const messages = await getMessages({locale})              │
│     <NextIntlClientProvider messages={messages}>             │
│       <ThemeProvider>                                        │
│         <MainNav />                                          │
│         {children}                                           │
│       </ThemeProvider>                                       │
│     </NextIntlClientProvider>                                 │
│     generateStaticParams: 所有 locale 预生成                  │
│                                                              │
│  3. 组件层 (useTranslation)                                  │
│     自定义 Hook 封装:                                         │
│       useTranslation('namespace') → t('key')                 │
│     命名空间:                                                 │
│       navigation, dashboard, chat, chat.experts,             │
│       settings, common                                       │
│                                                              │
│  4. 翻译文件 (messages/{locale}/)                             │
│     zh.json / en.json / ja.json / ko.json / de.json          │
│     每个文件包含所有命名空间的翻译                             │
└──────────────────────────────────────────────────────────────┘
```
